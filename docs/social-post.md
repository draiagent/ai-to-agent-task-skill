# 🚀 AI to Agent：把交辦的工作，做成可用的成果

你有沒有遇過：請 AI 幫忙，它回答得很完整，真正要用時，卻還得自己重排格式、補資料、檢查缺漏？問題往往出在交辦方式。只說「幫我做一下」，沒有交代範圍、資料與完成條件，很容易得到方向正確、卻無法直接使用的內容。

**AI to Agent，是一套以任務為核心的工作架構。**

啟動句是：「你是 AI to Agent，幫我完成以下任務。」這句話調用的是一組事先定義的工作規則：理解任務、規劃步驟、運用工具、檢查結果、完成交付。模型提供能力，架構提供方法，Prompt 則是調用入口。

**📥 第一步：先讓 Agent 讀懂規則。**

第一次使用，先提供本專案的 SKILL.md，或在支援自訂技能的平台載入技能包。若平台不支援安裝，也能把規則貼入對話。只輸入名稱，不能保證一個從未讀過架構的模型自動知道全部要求。

**📝 第二步：補齊四項交辦資訊。**

輸入資料，是它要根據哪些大綱、文件與數據工作；限制條件，是對象、篇幅、時限與不能做的事；交付形式，是你最後要拿到什麼；驗收標準，則是如何判斷這件事已經做好。

不需要把提示詞寫成論文，把這四項說清楚，就能減少來回猜測。缺少會影響結果的重要資訊，先補齊；低成本的小細節，可以讓 Agent 採合理假設並說明。

**🎓 實作案例：完成兩小時教案。**

你已經有課程大綱，希望 Agent 整理成可以授課的教材，就可以這樣交辦：

「你是 AI to Agent，請依提供的大綱製作兩小時教案。對象為初學者，使用繁體中文。請交付教案、練習單及評量題，確認流程合計 120 分鐘，練習和題目都對應學習目標。」

接著附上大綱與必要資料。Agent 應依原定範圍完成，安排執行順序、製作教材，檢查時數與內容。若大綱有疑點，應明確指出，讓你決定調整方向，而不是悄悄換成另一門課。

**✅ 第三步：用三個問題驗收。**

第一，成果完整嗎？約定的三份內容是否齊全？第二，證據清楚嗎？檢查過什麼、還沒確認什麼，有沒有分開說明？第三，成果可用嗎？教師能否照著授課，學員是否看得懂練習要求？

「文件已完成」和「學員已學會」要分開判斷。前者可以檢查教材，後者必須看實際作答或操作。沒有實測，就不能把學習成效寫成已驗證。

**🔁 第四步：發現落差，具體修正。**

不要只說「再好一點」，可以指出：「這段超過初學者程度，請換成一個生活案例，保持總時數不變。」修正後再核對標準，達標就交付。遇到缺資料或工具限制，則請 Agent 說明原因與下一步。

這套方法適合整理會議紀錄、依模板做簡報、依規則整理資料，以及其他範圍清楚的工作。它不會自動增加模型能力，但能讓交辦、執行與驗收更一致。

下一次，選一件你已經知道怎麼做、卻沒有時間完成的工作，把規則與資料交給 Agent。從一項可驗收的小任務開始，建立真正能重複使用的協作方式。

**完成任務，交付成果，才是 AI to Agent 的重點。**

把常做的任務保留成範例，下一次只更新資料與期限，就能重複使用。每次交付也留下簡短檢查紀錄，例如時數加總、缺漏欄位及未確認事項。這樣不只自己容易接手，同事也能理解成果如何產生，減少反覆詢問與返工。
